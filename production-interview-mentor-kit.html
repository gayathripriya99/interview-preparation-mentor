1. React.js

Focus on explaining concepts clearly and writing small examples—not memorising definitions alone.

Curriculum

  • Forms/validation, Context API, Redux Toolkit, TanStack Query, React Router, API states, performance, lazy loading, code splitting, error boundaries, testing, accessibility, structure, environment variables and production builds.

  • Build a searchable/filterable list.
  • Build a validated form with accessible errors.
  • Fetch API data with loading, error, retry, and empty states.
  • Use useMemo/useCallback only where justified.
  • Explain a real prior React feature from the language-learning platform.

Interview question bank

For each question, explain the concept, give a practical example, mention a trade-off, and be honest about whether you used it in production.

1. Explain React rendering and reconciliation.

Tests: React fundamentals. Outline: state/props/context changes can trigger rendering; React compares the new element tree with the previous one and updates the necessary UI. Keys help identify list items. Follow-up: What can cause unnecessary renders?

2. When would you use useEffect versus derived state?

Tests: state modelling. Outline: use effects to synchronise with external systems; calculate values from existing props/state during render when possible. Follow-up: How can redundant state become inconsistent?

3. What causes an effect loop?

Tests: dependency reasoning. Outline: an effect updates state, causing a render, and its dependencies change so the effect runs again. Check dependency identity and whether an effect is needed. Follow-up: What is a stale closure?

4. Explain useMemo versus useCallback.

Tests: performance and referential identity. Outline: useMemo caches a calculated value; useCallback caches a function reference. Use them when there is a measured or clear identity-related benefit, not by default. Follow-up: What are their costs?

5. What are stale closures?

Tests: JavaScript and React hooks. Outline: a function captures values from the render in which it was created; a later callback may observe an older value if dependencies or logic are wrong. Follow-up: When might a ref help?

6. Explain the JavaScript event loop and microtasks.

Tests: async execution. Outline: synchronous work runs on the call stack; asynchronous completions schedule callbacks; microtasks such as promise reactions are generally processed before the next task. Follow-up: Predict the output of a promise and setTimeout example.

7. How do Express middleware functions work?

Tests: backend request flow. Outline: middleware can inspect/modify request and response, end the response, or pass control with next; error middleware handles errors centrally. Follow-up: How do you order authentication and validation?

8. How would you design a secure CRUD API?

Tests: API design and security. Outline: define resources and status codes; validate inputs; authenticate and authorize; parameterize SQL; handle errors consistently; add rate limits, logging, tests and pagination. Follow-up: How would you prevent one user from reading another's records?

9. Explain SQL joins and when to use indexes.

Tests: relational data. Outline: joins combine related rows; indexes can speed reads/filtering/sorting but use storage and add write overhead. Use query plans to guide choices. Follow-up: Why might an index not be used?

10. What is a transaction and why does it matter?

Tests: data consistency. Outline: a transaction groups operations into a unit with ACID properties; commit or roll back to avoid partial updates. Follow-up: What problems can isolation levels prevent?

11. When would you use Python/FastAPI rather than Node.js?

Tests: system choices. Outline: consider existing stack, team expertise, ecosystem, workload, libraries, latency, operations and maintainability—not language popularity alone. Follow-up: How could both services work together?

12. What is an LLM and what is a context window?

Tests: GenAI foundations. Outline: an LLM generates tokens based on learned patterns and supplied context; the context window limits how much input/output context the model can process at once. Follow-up: How do token limits affect cost and design?

13. Explain RAG end to end.

Tests: applied GenAI. Outline: ingest and chunk sources, embed chunks, retrieve relevant content for a query, assemble context, generate a grounded answer, then evaluate and monitor it. Follow-up: How do you improve poor retrieval?

14. What are embeddings and vector search?

Tests: retrieval foundations. Outline: embeddings represent content as vectors; vector search retrieves vectors that are close under a chosen similarity/distance measure. Follow-up: Why can semantically similar retrieval still fail?

15. How would you reduce hallucinations?

Tests: reliability. Outline: ground answers in trusted retrieved sources, constrain output, provide abstention paths, evaluate with representative tests, and monitor failure cases. RAG helps but does not guarantee correctness. Follow-up: How would you measure groundedness?

16. What are ASR and TTS?

Tests: speech AI. Outline: ASR converts speech audio to text; TTS converts text to generated speech. Consider quality, latency, language support, privacy and failure handling. Follow-up: How would you evaluate transcription quality?

17. How would you connect speech AI to a React app?

Tests: end-to-end architecture. Outline: capture audio with consent, send it securely to a backend, validate/limit uploads, call ASR, return transcript/status, handle errors and protect credentials server-side. Follow-up: When is streaming useful?

18. How do you test and monitor a production API?

Tests: production readiness. Outline: unit/integration tests, validation and failure-path tests, structured logs, metrics, traces where useful, health checks and alerting. Follow-up: Which metrics help identify latency problems?

19. Explain the language-learning platform architecture and LSRW flow.

Tests: project depth. Outline: describe only what you remember: learner UI, React state, actual APIs, database responsibilities, and listening/speaking/reading/writing journeys. Clearly separate your work from your team's work. Follow-up: What was one difficult bug you fixed?

20. Describe one bug, how it was diagnosed, and what you learned.

Tests: ownership and problem solving. Outline: explain the symptom, reproduction, investigation, root cause, fix, validation, and prevention. Do not invent a story; use a real example. Follow-up: What would you do differently now?

  • React component structure and state flow.

  • PostgreSQL entities/relationships — label as proposed if not remembered.
  • Analytics/ETL, if applicable to your actual work.
  • Production bugs and fixes; testing, deployment, collaboration, trade-offs.
  • Clearly distinguish “I personally implemented” from “the team implemented.”

Deployment checklist for your own site

  • Keep project code in a Git repository; do not commit credentials or private data.
  • Run the production build locally and fix errors.
  • Push to GitHub, import the repository in Vercel, and use the framework's detected build settings.
  • For Vite static apps, build command is usually npm run build and output directory is dist.
  • Check mobile layout, links, tracker refresh behavior, and browser console.
